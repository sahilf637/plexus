# Plexus M0 — offline capture → linked map

## Context

M0 builds the core loop with **no AI provider**: press a global hotkey from any app → a small
capture window opens → paste anything → the item lands on the map instantly and within ~1 s is
linked by meaning to related items. This proves the map is worth looking at before any LLM work.

Agreed design constraints:
- **Files are the source of truth.** One `.md` note per item (frontmatter metadata + content, or
  + extracted text and a reference to an original file sitting beside it). SQLite is a rebuildable
  index. The final note format is used from day one.
- **Hotkey opens a capture window** (default). "Hotkey saves the clipboard directly" is an
  option in Settings.
- **Separate from DocBook.** Fresh code; Atomic (MIT, github.com/kenforthewin/atomic) is the reference.
- Svelte 5 frontend; thin, modular Rust; single-line commit messages.
- Primary dev machine: Ubuntu 26.04, GNOME 50 on Wayland; Rust 1.98, Node 23.
- Decided: hotkey **Ctrl+Alt+V** (rebindable); embeddings **bge-small-en-v1.5 int8** (swappable
  later via `meta.embed_model`); license **MIT**.

## Review notes (why this order / shape)

- **Riskiest piece first.** Global hotkey → focused window on GNOME Wayland is the one thing that
  can't be designed around later, so it's proven in step 2, before storage and linking.
- **Capture through the webview's paste event**, not a background clipboard read: the browser
  `paste`/`drop` events hand over text, HTML, images and files uniformly on every OS, and the
  window is focused so Wayland allows it. `arboard` is only needed for the optional
  "save clipboard directly" mode and the tray action.
- **"Never reject" from day one:** images and files pasted in M0 are saved as-is (original beside
  its note, no OCR/extraction yet). This exercises the asset half of the format now, so M1 only
  adds extractors.
- **Stable map:** existing nodes stay pinned while new ones are laid out; a full re-layout only
  happens when the user asks ("Tidy layout").

## Library format

```
~/Plexus/                                  (default; changeable in Settings)
  items/2026/10/rust-ownership-rules-k3f9.md
  items/2026/10/whiteboard-p8d4.md + whiteboard-p8d4.png
  .plexus/index.db                         (safe to delete; rebuilt)
```

Frontmatter: `plexus: 1, id (ULID), kind, title, captured, source?, language?, hash,
asset?, asset_hash?, mime?, original_name?, extracted?, links: []`, then the body (content, or
extracted text; empty for raw files in M0). File name = title slug (≤60 chars) + last 4 chars of
the ULID; the original keeps the same stem. Writes are temp-file + rename. YAML via a maintained
serde YAML crate (pick at scaffold time; must round-trip unknown keys).

## DB schema (`.plexus/index.db`, WAL)

- `items(id PK, path UNIQUE, kind, title, source_url, captured_at, body_hash, mtime, size,
  asset_path, asset_hash, mime, status[pending|linked|unlinkable|failed], pipeline_version)`
- `chunks(id INTEGER PK, item_id, ord, text)` + `vec_chunks` (sqlite-vec `vec0`, float[384], rowid = chunks.id)
- `items_fts` (FTS5: title, body)
- `edges(src, dst, kind, weight, reason, confidence, provenance, status, pipeline_version,
  created_at, PK(src,dst,kind))` — `similar` edges are undirected, stored with src<dst
- `layout(item_id PK, x, y)`; `meta(key, value)`: schema_version, embed_model, pipeline_version

## Steps (one single-line commit each)

0. **Docs** — `docs/OVERVIEW.md` gets a Storage section and the capture-window flow; `AGENTS.md`:
   prior art → Atomic, storage principle, one-line commits, this layout; `docs/plans/M0.md` =
   this plan; `LICENSE` (MIT, © 2026 Sahil Singh); drop "License" from Open decisions.
1. **Scaffold** — workspace, Tauri v2 + Svelte 5 + Vite (two entries); plugins: single-instance
   (forwards `--capture`), autostart, notification, global-shortcut; tray (Open Plexus, Capture…,
   Save clipboard, Quit); close-to-tray; tracing logs; settings JSON in the app config dir
   (library path, hotkey, hotkey action, start at login); `dev:ui` mock backend; `fetch-model`.
2. **Hotkey + capture window (spike first)** — capture window created hidden at startup
   (small, centred, always-on-top, no taskbar entry) so showing it is instant.
   Hotkey: Wayland → XDG GlobalShortcuts portal via `ashpd` (GNOME asks once to approve), passing
   the portal's activation token so GNOME gives the window focus; X11/macOS/Windows →
   `tauri-plugin-global-shortcut`. Fallbacks: failed registration shown in Settings with rebind,
   and `plexus --capture` for a desktop custom shortcut. **Exit check: on this machine, from
   another focused app, hotkey → window focused with the cursor in the paste zone.**
   Window UX: focused paste/drop zone ("Paste or drop anything · or type"); on paste it shows a
   preview card with the detected kind (Text / Code · lang / Link / Image / File); **Enter** saves
   (Ctrl+Enter while typing); **Esc** closes. After saving it stays ~2 s showing "Saved · linked
   to: A, B, C" as links arrive, then fades; any key closes it. Secrets show an inline warning
   with "Save anyway". Ctrl+V in the main window opens the same flow. Saving calls a stub
   command until step 3.
3. **Library + DB** — note read/write (frontmatter round-trip), asset copy beside the note,
   migrations, sqlite-vec loaded via the `sqlite-vec` crate (as Atomic does in
   `crates/atomic-core/src/db.rs`), startup **reconcile** (walk `items/`: new/changed → upsert +
   enqueue, missing → delete row/edges/layout; non-Plexus files ignored and logged).
   Deleting `index.db` rebuilds it.
4. **Save path (T0, <50 ms)** — `capture_save(payload)`: text/HTML (plain text kept in M0) or
   bytes + name/mime for images/files; detect `url` (single http(s) token) / `code` (fences,
   shebang, symbol density) / `text` / `image` / `file`; secret detector (known key/token
   prefixes, private-key blocks, JWTs, long high-entropy tokens); dedupe on normalized body hash
   or asset hash → "Already saved"; write note (+asset) → insert `pending` row → emit
   `item-added` → enqueue. "Save clipboard directly" mode/tray action reads via `arboard` and
   uses the same path, with an OS notification instead of the window.
5. **Pipeline (T1, <1 s)** — one worker (tokio task + channel; `pending` rows re-queued on start).
   Markdown-aware chunker adapted from Atomic `crates/atomic-core/src/chunking.rs` (sized for
   bge-small's 512-token limit: target ~1200 chars, max ~1600, small overlap). Embed with
   `fastembed` (bundled ONNX model, lazy load, unload after 2 idle min). Link like Atomic's
   `compute_semantic_edges_for_atom` (`crates/atomic-core/src/embedding.rs:2320`): per-chunk
   kNN on `vec0` → best chunk pair per target item → threshold (start 0.65, tuned in step 8) →
   top 8 → replace the item's `similar` edges. Raw images/files embed their title/filename only
   (weak links; `unlinkable` if nothing useful). Model change in `meta` re-embeds everything.
   Emit `item-linked {id, edges}`.
6. **Map UI** — Sigma.js + Graphology (+ `@sigma/edge-curve`); node size by degree, color by kind,
   edge opacity by weight, each node shows its top-5 edges by default. Positions from `layout`;
   a new node appears with a pulse, moves to the weighted centroid of its neighbours on
   `item-linked`; ForceAtlas2 worker (`graphology-layout-forceatlas2/worker`) settles new nodes
   with existing ones pinned; positions saved debounced; "Tidy layout" re-runs it fully.
   Hover highlights neighbours; click opens ItemPanel (title, kind, captured, source link,
   rendered body or image preview / "open file", related items with %); hybrid search (FTS5 +
   vector, reciprocal rank fusion) flies the camera to results; empty state "Press Ctrl+Alt+V
   anywhere to add something".
7. **URLs** — after capture, fetch (10 s timeout) + readability extraction (`dom_smoothie`, as in
   Atomic `crates/atomic-core/src/ingest/extract.rs`) → rewrite note body/title → embed.
   Offline/failed → stays a bare link, retried on next start.
8. **Tune + verify** — seed, measure, tune threshold/top-k, fix what the map reveals.

## Verification

- `cargo test`: frontmatter round-trip, asset placement, kind detection, secret detector,
  dedupe, reconcile against a temp library (new/edited/deleted notes and assets, deleted DB),
  chunk sizes, edge selection with synthetic vectors. `cargo clippy`, `npm run check`.
- `npm run seed` → ~300 notes (Wikipedia summaries across ~15 topics, code snippets, URLs) in a
  scratch library; start the app on it: reconcile + pipeline finish, map shows visible groups.
- Logged timings: save → `item-added` < 50 ms; → `item-linked` < 1 s (model warm);
  hotkey → capture window visible < 150 ms.
- Manual on GNOME/Wayland: approve the portal shortcut; from a browser/terminal press Ctrl+Alt+V →
  window focused → paste text / a link / a screenshot / drop a PDF → saved, node appears and
  links; switch Settings to "save clipboard directly" → notification path works; kill
  mid-pipeline → resumes; edit a note in a text editor → re-linked on restart; delete
  `index.db` → rebuilt; paste an API key → inline warning.
- `npm run dev:ui` in the browser pane for UI checks of both windows (light/dark screenshots).

## Out of scope for M0

LLM enrichment, topic clustering/labels, OCR / PDF-DOCX text extraction, HTML→markdown
conversion, clipboard watching, the Ask agent, in-app editing, file watcher (reconcile happens
at startup only).

# Plexus M1 — curate the map, stronger links, real text from files

## Context

M0 captures anything and links it by meaning, offline. M1 does two things:

- **A. Curate the map** (small): delete items, and make link strength easier to read and work with.
- **B. Extractors**: files and images get real text, so they link like any note instead of by name.

Decided (2026-10-05):
- **Linking stays fully automatic. There is no accept/reject/approval flow**, because review
  queues are extra work for someone who only wants to use the app for knowledge. Strength tiers
  (`strong`, `related`, `maybe`) tell the user what to trust; weak links are drawn faintly and
  can be hidden. The unused `rejected` edge status stays in the schema, untouched.
- **OCR is a small, good-enough local engine**, kept swappable: when an LLM provider is
  connected (M2), vision replaces it. Images with no readable text stay linked by name or note
  only (capped at `maybe`) until a provider can describe them. No local image-embedding model.
- **Deleted items go to a trash inside the library** (`.plexus/trash/`), not the OS trash:
  undo is reliable and identical on every OS, and it needs no new dependency. Batches are purged
  after 30 days.

## A. Curate the map

1. **Delete item** — panel button, right-click menu and the `Delete` key on the map; shift-click
   to select several. The note, its original and its attachments move to
   `.plexus/trash/<batch>/` (same relative paths), the index row, chunks, vectors, edges and
   layout are removed, and the map drops the node live. A toast offers **Undo**, which moves the
   files back, re-indexes and re-links them (the item returns without its old position).
   Reconcile ignores `.plexus/`, so a trashed note never comes back by itself.
2. **Link reasons without an LLM** — every `similar` link gets a short plain reason from what is
   objectively shared: top shared keywords ("both mention rust, borrow checker"), same website,
   saved together. Stored in `edges.reason`, shown in the item panel.
3. **Strength** — shown the same way everywhere (line weight on the map, a bar and tier group per
   row in the panel, the Strong · Related · All filter). Tiers stay decided by embedding
   similarity alone: same-site was considered as a boost but dropped, since a site like Wikipedia
   would tie unrelated pages together; it only appears in a link's reason. A pipeline-version
   bump re-links existing libraries so they get reasons.
4. **Link to… (optional)** — pick an item in the panel and make a hand-made link: `links:` in the
   note's frontmatter, read by reconcile as a `user` edge, always `strong`.

## B. Extractors

Each extractor stamps `extracted: <tool>@N` in the note. A newer extractor may re-run while the
stamp names a tool; `extracted: edited` is never overwritten. Failure keeps the item as a raw file
and never blocks capture.

1. **Extractor framework** + plain-text files (`.md`, `.txt`, code files; language detected).
2. **Rich HTML → markdown**, keeping the source URL.
3. **Images: OCR** with a small local engine (first `ocrs`, replaced by PP-OCRv6 small, see Status; ~30 MB bundled
   like the embedding model; spike on real screenshots first). Text goes in the note body.
4. **PDF, DOCX, EPUB** text, with page markers for later citations.
5. **Clipboard watching (opt-in)**: off by default, skips password-manager sources, same secret
   check and dedupe as capture.
6. Items with extracted text drop the name-only cap; items still without text are marked as
   waiting for a provider.

## Status

All steps are implemented. Differences from the plan: same-site is a reason only, not a tier
boost; clipboard watching can't tell which app a copy came from (it skips short copies and
anything the secret detector flags), and GNOME/Wayland doesn't let apps read the clipboard in
the background; pasted HTML keeps no source URL, since browsers on Linux don't provide one. A
dropped `.md` file is stored as `.markdown`, because the library treats every `.md` as a note.
Link reasons rank shared words by use × rarity. OCR first used `ocrs` (~12 MB), which read photos and screenshots poorly; it was replaced by PaddleOCR PP-OCRv6 small (~30 MB, via `rapidocr-core` on the app's own ONNX Runtime), which reads accents, CJK and noisy screenshots correctly, in about 2–4 s per image. Its models unload after 2 idle minutes.

## Steps (single-line commits)

1. Delete item: trash, Undo, UI (panel, menu, key), multi-select.
2. Link reasons and strength signals, strength display.
3. Optional manual links.
4. Extractor framework, plain-text files, HTML → markdown.
5. OCR spike, then OCR.
6. PDF, DOCX, EPUB.
7. Opt-in clipboard watching.
8. Tune and verify on the seed library.

## Verification

- `cargo test`: trash and restore round-trip (note + original + attachments), a trashed note is
  not re-added by reconcile, restore re-indexes, purge of old batches, deleting while queued;
  reason generation; extractors against small fixtures.
- Manual: delete from panel, menu and key; undo; delete several; delete an item mid-link; delete
  `index.db` after deleting items (nothing returns); restore after a restart.
- `npm run dev:ui` for UI checks.

## Out of scope for M1

LLM enrichment, any accept/reject flow, topics, the Ask agent, in-app editing, a file watcher.
